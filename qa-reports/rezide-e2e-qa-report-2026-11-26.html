Rezide frontend · End-to-End QA Report

Full test of the Next.js site: every public page in a real browser at three screen sizes, signed-in areas, the live backend, and a line-by-line code review.

Date 26 Nov 2026 Branch module/projects (HEAD fb50e89 + uncommitted SEO work) Build production (next build + next start) Backend live api.rezide.in (mocking off) Browser Chrome (headless) at 1440 px, 768 px, 375 px

Verdict: not ready for release

The site loads cleanly: no page crashed and none scrolls sideways on any screen size. But two critical security problems must be fixed first: the live backend gives realtors' PAN numbers, phone numbers and emails to anyone, and the sign-in page can send users to an outside website. Several important features also don't work in production: the whole realtor dashboard, Realtor Corner's callback and trial forms, map pins, and some property searches, which fail completely.

How it was tested

  • Automated checks: TypeScript typecheck, ESLint on the whole project, all 419 unit/component tests, and a production build.
  • Browser test: each page was opened in headless Chrome at desktop (1440 px), tablet (768 px) and phone (375 px) widths. For each load it recorded:
    • HTTP status, page title and headings
    • console errors and failed network requests
    • broken images and horizontal overflow
    • unlabelled buttons, links and inputs, and duplicate ids
    • text such as "undefined", "NaN", "₹ 0" or "0 Towers"
  • Signed-in areas: the account (seeker and owner) and every realtor dashboard page were opened with a test session placed in the browser. The site keeps its session in localStorage, which makes this possible.
  • Server checks: security headers, status codes for unknown pages, API error handling, robots.txt and sitemaps.
  • Code review: three separate reviews covered search/properties/listing, projects/compare/locality/developer, and realtors/dashboard/account/auth. Each finding was traced end to end, and data questions were checked with read-only calls to the live backend.
Limits, stated honestly:
  • No real SMS sign-in was done, and no real form was submitted, to avoid sending real leads.
  • The signed-in tests used a test user id that doesn't exist on the backend.
  • Payment was not tested; checkout is disabled in the app.
  • Findings marked Code review were traced through the code but not clicked through in a browser.
  • Findings marked Verified were reproduced in the browser, by curl, or against live data.

What works well

  • No page scrolls sideways at 1440, 768 or 375 px on any of the 36 public pages.
  • No page crashed. There were no JavaScript runtime errors and no broken images.
  • Security headers are in place: Content-Security-Policy, X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy and HSTS. .env is not committed.
  • The frontend never sends developer bank/PAN details or realtor identity documents to the browser; its allowlists work. The PII problem below is in the backend.
  • The new SEO works as intended:
    • Old project, locality and developer URLs redirect with HTTP 308.
    • Canonical URLs, metadata and JSON-LD are present.
    • Sitemaps list 9,534 projects, 1,786 localities and 3,295 developers.
    • Empty pages are marked noindex.
  • TypeScript typecheck passes, the production build succeeds, and 417 of 419 tests pass.
